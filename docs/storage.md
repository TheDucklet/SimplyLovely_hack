# Хранилище PostgreSQL

Хранилище переносит данные конвейера и расчёты модели из файлов Parquet в PostgreSQL 16 с PostGIS, чтобы API в контуре банка работал с базой, а не с файлами, и права на чтение и загрузку были разделены. Файловый режим остаётся режимом по умолчанию для разработки.

## Запуск

База запускается в Docker из `docker-compose.yml`. Пароли задаются в `.env`, пример лежит в `.env.example`:

| Переменная | Назначение |
| --- | --- |
| `POSTGRES_PASSWORD` | пароль суперпользователя, нужен только контейнеру |
| `GEOSTART_DB_LOADER_PASSWORD` | пароль роли загрузки `geostart_loader` |
| `GEOSTART_DB_API_PASSWORD` | пароль роли чтения `geostart_api` |
| `GEOSTART_DB_HOST`, `GEOSTART_DB_PORT`, `GEOSTART_DB_NAME` | адрес базы, по умолчанию `127.0.0.1:55433/geostart` |
| `GEOSTART_STORAGE` | `files` (по умолчанию) или `postgres` |

```
docker compose up -d --wait db
uv run python -m geostart.storage load --city all
```

Команда `load` применяет схему из каталога `sql/` и загружает в базу признаки ячеек, конкурентов, адреса, расчёты модели из `data/scores/` и версию данных. Каждый город загружается в отдельной транзакции, повторная загрузка заменяет строки города целиком. API переключается на базу переменной `GEOSTART_STORAGE=postgres`. Порт базы публикуется только на `127.0.0.1`.

## Схема и роли

| Объект | Содержание |
| --- | --- |
| `geo.hex_features` | признаки ячеек H3, первичный ключ `(city, h3)` |
| `geo.competitors` | точки конкурентов, пространственный индекс GiST |
| `geo.addresses` | адреса и поле поиска в нижнем регистре с «е» вместо «ё», индекс триграмм `pg_trgm` |
| `geo.scores` | расчёты модели по ячейкам, проверки упорядоченности квантилей и уровня риска |
| `geo.data_versions` | версия данных и время загрузки по городу |

Геометрия точек вычисляется базой из широты и долготы (столбец `geom`, генерируемый). Схемой `geo` владеет роль `geostart_loader`, роль `geostart_api` получает только `USAGE` на схему и `SELECT` на таблицы через права по умолчанию. Создание объектов в схеме `public` запрещено всем. Роли и расширения создаёт скрипт `docker/db/init/01_roles.sh` при первом запуске контейнера, поэтому смена паролей в `.env` требует пересоздания тома командой `docker compose down -v`.

## Что читается из базы

В режиме `postgres` из базы читаются `/health`, `/hexes`, `/competitors` и `/search`. Отчёт по адресу `/report` по-прежнему строит модель по файлам `data/processed/`, так как модель Романа читает Parquet напрямую. Перевод модели на базу запланирован на второй спринт. Если база недоступна, API отвечает кодом 503 с подсказкой, если город не загружен – кодом 404 с командой загрузки.

## Время ответа

На данных Москвы ответ `/hexes` из базы приходит за 120 мс против 760 мс при первом чтении Parquet, `/competitors` за 70 мс, поиск адреса за 80 мс. Загрузка Москвы и Тулы занимает около 5 секунд.

## Тесты

Тесты `tests/test_storage.py` запускаются при `GEOSTART_TEST_DATABASE=1` и поднятой базе, иначе пропускаются. Тесты загружают синтетическую Тулу и удаляют часть расчётов Москвы, поэтому после них реальные данные нужно загрузить заново командой `load`. В CI для них есть отдельная задача `storage` с одноразовой базой и тестовыми паролями.
