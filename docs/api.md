# API

API построен на FastAPI и запускается командой `uv run uvicorn geostart.api.main:app --reload`. Пути, параметры и примеры ответов описаны в [contracts.md](contracts.md), интерактивная документация доступна по адресу `/docs` запущенного сервиса.

## Режимы работы

| Режим | Переменная | Поведение |
| --- | --- | --- |
| Реальные данные | `GEOSTART_USE_MOCKS=false` (по умолчанию) | карта читает `data/scores/<city>_<niche>.parquet`, конкуренты и адреса читаются из `data/processed/<city>/`, отчёт строится функцией `geostart.model.evaluate_location` |
| Заглушки | `GEOSTART_USE_MOCKS=true` | ответы строятся из синтетических данных генератора, формулы в `src/geostart/api/mocks.py` |

Пути `/health`, `/cities` и `/niches` работают в обоих режимах. В режиме реальных данных `/health` возвращает самую свежую дату сбора данных по городам, а при старте API читает файл `.env` из корня репозитория.

Перед запуском в режиме реальных данных нужны данные конвейера (`uv run python -m geostart.pipeline run --city all` или архив данных) и расчёт городов:

```
uv run python -m geostart.model score --city all --niche all
```

Модуль `src/geostart/api/data_backend.py` кэширует прочитанные файлы Parquet по пути и времени изменения, поэтому пересчёт города подхватывается без перезапуска API.

## Время ответа

На данных Москвы внутри МКАД ответ `/hexes` для 8717 ячеек весит около 1 МБ без сжатия и приходит примерно за 0,8 с, отчёт `/report` по адресу после прогрева кэша строится за 0,4-0,9 с (замер 2026-10-18). Ответы больше 1000 байт сжимаются gzip, если клиент передаёт заголовок `Accept-Encoding: gzip`, что браузеры делают сами.

При старте API заранее строит структуры модели для всех городов и ниш (`src/geostart/api/data_backend.py:warm_model_cache`), на данных 2026-10-18 это занимает около 6 секунд. После этого первый отчёт по адресу приходит за 0,4-0,9 с вместо 2-3 с. Город без данных пропускается с предупреждением в журнале, прогрев отключается переменной `GEOSTART_WARMUP=false`, в режиме заглушек он не выполняется.

## Поиск адреса

Запрос разбивается на слова, буква «ё» приравнивается к «е», регистр не учитывается. Адрес попадает в выдачу, если содержит все слова запроса. Первыми идут адреса, у которых номер дома точно совпадает с числом из запроса, затем адреса, начинающиеся с первого слова, затем остальные по алфавиту. Выдача ограничена 10 адресами.

## Ошибки

Тексты ошибок пишутся по-русски в поле `detail` и объясняют, что сделать пользователю.

| Код | Когда |
| --- | --- |
| 404 | неизвестный город или ниша, город не загружен конвейером или не рассчитан моделью (в тексте команда, которую нужно выполнить) |
| 422 | точка вне границы города, неположительная площадь или ставка аренды, некорректные параметры запроса |

Ошибки проверки параметров FastAPI по умолчанию отдаёт списком на английском. Обработчик `src/geostart/api/validation.py` заменяет его одной строкой на русском с названием поля, например «Значение поля «площадь» должно быть больше 0», поэтому поле `detail` всегда содержит строку.

## API v2

Пути `/api/v2/economics`, `/api/v2/credit-check`, `/api/v2/norms/{niche}` и `/api/v2/credit-products` отдают финансовый движок из [economics.md](economics.md). Формат запросов и ответов описан в разделе «HTTP API v2» файла [contracts.md](contracts.md), машиночитаемый контракт лежит в [api-v2.openapi.json](api-v2.openapi.json).

Ошибки второй версии приходят с типом `application/problem+json` и полями `type`, `title`, `status` и `detail`, у ошибок проверки запроса есть ещё список `errors` с путём к полю и текстом на русском. Обработчики `src/geostart/api/validation.py:validation_error_handler` и `http_error_handler` выбирают формат по префиксу пути, поэтому ответы первой версии сохраняют прежнее поле `detail`.

Расчёт по источнику `geostart` на данных Тулы занимает около 3,5 с при первом запросе к ячейке и использует тот же кэш модели, что и `/api/v1/report`. Источники `revenue` и `traffic` не читают геоданные и не требуют расчёта города. В режиме заглушек источник `geostart` заменяется выручкой заглушки отчёта v1 с поставщиком «демо-режим без данных города», а зарплату нужно передать в поле `operations.salary_rub_month`, если файла вакансий города нет.

## Заглушки

Выручка ячейки в заглушке растёт с числом жителей и работающих и падает с числом конкурентов в радиусе трёх колец H3 (около 500 м). Расходы включают аренду по условной ставке города, зарплаты со взносами 30%, себестоимость, налог 6% с выручки и прочие расходы. Уровень риска определяется рентабельностью: убыток означает высокий риск, рентабельность до 15% – средний, выше – низкий. Коэффициенты подобраны так, чтобы на карте встречались все три уровня риска, и не описывают реальную экономику ниш.

CORS разрешён для адресов из `GEOSTART_CORS_ORIGINS`, по умолчанию для сервера разработки Vite `http://localhost:5173` и проверки сборки `npm run preview` на `http://localhost:4173`.
