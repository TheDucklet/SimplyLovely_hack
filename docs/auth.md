# Вход, роли и журнал обращений

ГеоСтарт не хранит учётные записи. Пользователь входит через сервер единого входа банка по протоколу OpenID Connect, сервис получает от него идентификатор, имя и роли. На стенде вместо сервера банка работает встроенная заглушка `/idp`, в контуре банка её выключают и указывают адрес сервера банка.

## Как устроен вход

Интерфейс сам токены не хранит. Вход выполняет API по схеме «сервер для интерфейса».

1. Интерфейс получает от API ответ 401 и открывает `/api/auth/login`.
2. API перенаправляет браузер на сервер входа с кодом авторизации и PKCE (S256), `state` и `nonce` лежат в подписанной куке `geostart_login` на 10 минут.
3. После входа сервер возвращает браузер на `/api/auth/callback`. API обменивает код на токены по внутреннему адресу, проверяет подпись `id_token` по ключам сервера, издателя, получателя и `nonce`.
4. API ставит куку `geostart_session` на 8 часов с флагами HttpOnly и SameSite=Lax, внутри подписанные HMAC идентификатор, имя и роли. Флаг Secure ставится, когда `GEOSTART_PUBLIC_URL` начинается с `https://`.

Системы банка, например кабинет ВТБ Бизнес со встроенным отчётом, могут обращаться к API без браузера. Для этого в заголовке `Authorization: Bearer` передаётся токен доступа сервера входа, API проверяет подпись, издателя и получателя `GEOSTART_OIDC_AUDIENCE`.

Параметр `next` у входа принимает только путь на том же сайте, адреса вида `//host` и `https://host` заменяются на `/`. Если стенд открыт по другому имени хоста, чем `GEOSTART_PUBLIC_URL`, вход сначала переводит браузер на основной адрес, иначе кука входа потерялась бы при возврате.

## Роли

| Роль | Код | Права |
| --- | --- | --- |
| Предприниматель | `entrepreneur` | карта, отчёт по адресу, финансовая модель, нормативы |
| Кредитный специалист | `credit_officer` | права предпринимателя и проверка бизнес-плана заёмщика `POST /api/v2/credit-check` |
| Аналитик | `analyst` | права предпринимателя и сводка обращений по дням, городам и нишам без пользователей |
| Администратор | `admin` | права аналитика и журнал обращений с псевдонимами пользователей |

Проверку бизнес-плана видят только кредитные специалисты, так как план содержит сведения клиента банка. Администратор отвечает за работу сервиса и бизнес-планы не проверяет. В интерфейсе кнопка «Кредитный специалист» показывается только при праве `credit_check`.

| Права | Пути |
| --- | --- |
| без входа | `GET /api/v1/health`, `/api/auth/*`, `/idp/*` |
| `view_map` | `GET /api/v1/cities`, `/niches`, `/hexes`, `/competitors`, `/search` |
| `location_report` | `POST /api/v1/report`, все пути `/api/v2/*`, кроме проверки бизнес-плана |
| `credit_check` | `POST /api/v2/credit-check` |
| `access_stats` | `GET /api/admin/access-stats` |
| `access_log` | `GET /api/admin/access-log` |

Новые пути `/api/v2` автоматически требуют `location_report`. Без входа API отвечает 401, при нехватке прав 403, для `/api/v2` в формате `application/problem+json`.

## Журнал обращений к отчётам

Журнал пишет API по каждому запросу к `POST /api/v1/report`, `/api/v2/economics`, `/api/v2/credit-check` и `/api/v2/sensitivity`, в том числе отклонённому. Записи лежат в `data/audit/access-ГГГГ-ММ-ДД.jsonl`, каталог меняется переменной `GEOSTART_AUDIT_DIR`.

| Поле | Содержание |
| --- | --- |
| `time` | время ответа в UTC |
| `request_id` | случайный идентификатор записи |
| `user` | псевдоним, первые 16 знаков HMAC-SHA256 от идентификатора пользователя на ключе сессий, `null` без входа |
| `roles` | роли пользователя |
| `action` | `location_report`, `economics`, `credit_check` или `sensitivity` |
| `city`, `niche` | код города и ниши из справочника, `unknown` для чужих значений, `null` без поля |
| `status` | код ответа |
| `duration_ms` | время обработки |

Координаты, адрес, площадь, аренда, выручка, суммы кредита и другие поля запроса в журнал не попадают. Город и ниша берутся только из справочника, поэтому произвольный текст из запроса в журнал не проходит. По псевдониму банк находит пользователя, вычислив HMAC от идентификатора на том же ключе, у команды и у внешних лиц такой возможности нет. Срок хранения файлов задаёт политика банка, при выключенном входе журнал не ведётся.

`GET /api/admin/access-log?since=ГГГГ-ММ-ДД&limit=200` возвращает записи от новых к старым, по умолчанию за 7 дней. `GET /api/admin/access-stats?days=30` возвращает число обращений по дням, действиям, городам, нишам и исходу `ok`, `denied` или `error`.

## Настройка

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `GEOSTART_AUTH_MODE` | `off`, на стендах `oidc` | `off` выключает вход для разработки, все права открыты, журнал не ведётся |
| `GEOSTART_PUBLIC_URL` | на стендах адрес стенда | адрес, по которому пользователи открывают сервис, из него строится адрес возврата |
| `GEOSTART_OIDC_ISSUER` | с заглушкой `GEOSTART_PUBLIC_URL/idp` | издатель сервера входа банка |
| `GEOSTART_OIDC_INTERNAL_URL` | с заглушкой `http://127.0.0.1:8000/idp` | внутренний адрес сервера входа для обмена кода и ключей, если он отличается от издателя |
| `GEOSTART_OIDC_CLIENT_ID` | `geostart` | идентификатор клиента у сервера входа |
| `GEOSTART_OIDC_CLIENT_SECRET` | с заглушкой создаётся сам | секрет клиента |
| `GEOSTART_OIDC_AUDIENCE` | идентификатор клиента | получатель токенов доступа систем банка |
| `GEOSTART_OIDC_ROLES_CLAIM` | `roles` | поле токена с ролями, вложенные поля через точку, например `realm_access.roles` |
| `GEOSTART_OIDC_ROLE_MAP` | пусто | соответствие групп банка ролям ГеоСтарт, например `SME_CREDIT=credit_officer,GEO_ADMIN=admin` |
| `GEOSTART_SESSION_SECRET` | с заглушкой создаётся сам | ключ подписи сессий и псевдонимов, не короче 32 знаков |
| `GEOSTART_SESSION_HOURS` | `8` | срок сессии |
| `GEOSTART_IDP_STUB` | `false`, на стендах `true` | включает заглушку `/idp` |
| `GEOSTART_AUDIT_DIR` | `data/audit` | каталог журнала |

С заглушкой секрет клиента, ключ сессий и ключ подписи токенов создаются при первом запуске в `data/auth/` и переживают перезапуск. Без заглушки секреты задаются в `.env`, при нехватке настроек API не стартует и называет недостающие переменные.

## Заглушка единого входа

Заглушка `/idp` реализует нужную сервису часть OpenID Connect. В неё входят адрес настроек `/.well-known/openid-configuration`, страница входа `/authorize`, выдача токенов `/token` с проверкой секрета клиента и PKCE, ключи `/jwks`, `/userinfo` и выход `/logout`. Токены подписаны RS256, код авторизации действует 2 минуты и принимается один раз.

Пароля нет, на странице входа выбирается один из четырёх демонстрационных пользователей из `config/auth_stub_users.yaml`, по одному на роль. Заглушка принимает только клиента ГеоСтарт и адрес возврата `GEOSTART_PUBLIC_URL/api/auth/callback`.

## Подключение к серверу входа банка

1. Банк регистрирует клиента `geostart` с адресом возврата `https://<адрес ГеоСтарт>/api/auth/callback` и адресом после выхода `https://<адрес ГеоСтарт>/`, тип клиента конфиденциальный, поток authorization code с PKCE.
2. В `.env` задаются `GEOSTART_IDP_STUB=false`, `GEOSTART_PUBLIC_URL`, `GEOSTART_OIDC_ISSUER`, `GEOSTART_OIDC_CLIENT_SECRET` и `GEOSTART_SESSION_SECRET`.
3. Роли передаются в токене. Для Keycloak это обычно `GEOSTART_OIDC_ROLES_CLAIM=realm_access.roles`, группы банка сопоставляются ролям через `GEOSTART_OIDC_ROLE_MAP`.
4. Пользователь без ролей ГеоСтарт получает ответ 403 после входа.
