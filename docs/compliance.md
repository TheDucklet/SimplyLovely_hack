# Защита данных и требования регуляторов

Документ описывает состав обрабатываемых данных, применение Федерального закона № 152-ФЗ «О персональных данных» и Федерального закона № 115-ФЗ «О противодействии легализации (отмыванию) доходов, полученных преступным путём, и финансированию терроризма», модель угроз по ГОСТ Р 57580.1-2017, перечень программных средств с лицензиями и меры, которые уже реализованы в сервисе. Он продолжает `docs/security.md` и готовится к пилоту в контуре банка.

## Классификация данных

Сервис работает с пятью категориями сведений. Открытые геоданные и параметры ниш не связаны с людьми, сведения об организациях берутся из государственных реестров, данные запроса описывают место и параметры расчёта, данные банка поступают обезличенными агрегатами, журнал обращений хранит псевдоним пользователя. Персональные данные в явном виде обрабатываются только при встраивании сервиса в интерфейс банка, когда на вход подаётся идентификатор клиента.

| Категория | Состав | Источник | Чувствительность | Регулирование |
| --- | --- | --- | --- | --- |
| Открытые геоданные | здания, точки интереса, границы, адреса домов, численность населения | OpenStreetMap, Росстат, портал открытых данных Москвы | нет | лицензия ODbL, условия портала открытых данных |
| Параметры ниш и нормативов | средние чеки, частота покупок, аренда, налоги, кредитные ставки | исследование команды, открытые обзоры, нормативные акты | нет | ссылки на источники в файлах `research/` |
| Сведения об организациях | название, адрес, ИНН, выручка и расходы из отчётности | ГИР БО Федеральной налоговой службы, реестр малого и среднего предпринимательства | нет, персональные данные руководителей не переносятся | 152-ФЗ не применяется, состав ИНФС проверяется при публикации |
| Параметры запроса | город, ниша, координаты точки, площадь, ставка аренды, сумма кредита | пользователь сервиса | коммерческая тайна предпринимателя | режим коммерческой тайны по статье 1465 Гражданского кодекса |
| Данные банка в пилоте | обезличенные агрегаты оборота эквайринга по ячейке H3 и группе ОКВЭД | подразделение банка внутри контура | коммерческая тайна банка | внутренние стандарты банка, 152-ФЗ при попадании персональных данных в исходные выгрузки |
| Журнал обращений | время, действие, код города и ниши, код ответа, роли, псевдоним пользователя | сервис | псевдонимизированные данные | 152-ФЗ в части обезличивания, политика хранения банка |

## Персональные данные и 152-ФЗ

В текущем виде сервис персональные данные не обрабатывает. Запрос к расчёту содержит город, нишу и координаты точки, отчёт считается заново и не сохраняется, в журнал попадают псевдонимы вместо идентификаторов. Оператором персональных данных в этой схеме никто не становится, потому что субъект данных не определён.

При встраивании в интерфейс ВТБ Бизнес состав данных меняется. Сервис получает идентификатор клиента из сервера единого входа банка и, в сценарии бизнес-плана для индивидуального предпринимателя, фамилию и инициалы заёмщика для титульного листа. С этого момента сервис становится обработчиком персональных данных, а оператором остаётся банк, если обработка идёт по его поручению.

| Требование 152-ФЗ | Что нужно сделать | Состояние |
| --- | --- | --- |
| Статья 18.1, локализация баз данных | размещение серверов с персональными данными на территории Российской Федерации | выполняется по умолчанию при развёртывании в контуре банка |
| Статья 9, согласие субъекта | согласие клиента на обработку его данных в кредитном процессе оформляет банк в своих документах | не сделано, за банком |
| Статья 22, уведомление Роскомнадзора | уведомление подаёт оператор, то есть банк | не сделано, за банком |
| Статья 5, минимизация и сроки хранения | отчёт в карточке клиента хранится по политике банка, сервис отчёт не хранит | сделано в части сервиса |
| Статья 19, меры защиты | шифрование канала, разграничение ролей, журнал доступа без координат | сделано частично, см. раздел про реализованные меры |
| Статья 18, информирование субъекта | уведомление клиента о расчёте выдаёт интерфейс банка | не сделано, за банком |

Псевдоним в журнале строится как код аутентификации сообщения на ключе сессий от идентификатора сервера единого входа, обратное сопоставление возможно только на стороне банка. Если банк потребует вернуть полный идентификатор, сервис должен перейти на хранение журнала в контуре банка без выгрузки.

## Противодействие легализации доходов и 115-ФЗ

Сервис не проводит платежи, не открывает счета и не анализирует операции клиентов, поэтому обязанности по 115-ФЗ на него не распространяются. Требования применяются к процессам банка, в которые попадает отчёт.

| Обязанность банка по 115-ФЗ | Как связана с сервисом |
| --- | --- |
| Идентификация клиента по статье 7 | сервис получает результат идентификации от банка, повторно её не выполняет |
| Оценка риска клиента | отчёт по финансовой модели не влияет на оценку риска по 115-ФЗ, решение остаётся за подразделением финансового мониторинга |
| Хранение сведений об операциях | сервис операций не хранит, данные пилота поступают обезличенными агрегатами |
| Сообщение о подозрительных операциях | сервис такие сообщения не формирует, признаков операций в нём нет |
| Проверка деловой репутации | бизнес-план заёмщика не заменяет проверку по перечням и реестрам банка |

Ограничение ответственности нужно закрепить в акте пилота. Финансовая модель служит подсказкой кредитному специалисту и не является единственным основанием для решения по заявке.

## Модель угроз по ГОСТ Р 57580.1-2017

Модель угроз строится по трём уровням защиты, установленным стандартом для финансовых организаций. Для пилота заявлен второй уровень, при котором сервис обрабатывает сведения ограниченного доступа, но не хранит платёжные данные и сведения о клиентах сверх необходимого.

| Угроза | Категория по стандарту | Оценка | Мера |
| --- | --- | --- | --- |
| Подмена или порча открытых данных при загрузке | нарушение целостности | высокая, модель чувствительна к аренде и слоям OSM | контрольные суммы пакета, проверка распределений перед подключением, закреплённая дата выгрузки |
| Некорректный расчёт из-за неверных параметров запроса | нарушение целостности | средняя | проверка схем на входе API, ограничения на координаты, площадь и денежные суммы |
| Доступ к отчётам клиента без прав | нарушение конфиденциальности | высокая | вход через OpenID Connect, четыре роли, проверка права на каждом пути API |
| Раскрытие планов предпринимателя через журнал | нарушение конфиденциальности | средняя | журнал без координат и финансовых параметров, псевдоним вместо идентификатора |
| Утечка ключей и учётных данных | нарушение конфиденциальности | средняя | файл `.env` исключён из репозитория, ключи выдаются через хранилище секретов банка |
| Уязвимости в сторонних библиотеках | программная атака | средняя | версии закреплены в файле блокировки зависимостей, план сканирования зависимостей в сборке |
| Обращение к внешней сети из контура | нарушение ограничений трека | высокая | подложка карты и шрифты лежат в образах, запросов наружу нет, это проверяется автоматическим тестом |
| Отказ в обслуживании | нарушение доступности | низкая для пилота | ограничение частоты на шлюзе банка, изоляция контейнеров |
| Поддельные числа в пояснении языковой модели | нарушение достоверности | низкая, функция выключена | функция выключена по умолчанию, при включении проверяется, что каждое число есть в отчёте, модель запускается на своём оборудовании |

Уровень защиты по стандарту и перечень применяемых мер согласуются со службой информационной безопасности банка на этапе пилота. Для соревнования достаточно показать, что схема читает требования стандарта и не противоречит им.

## Программное обеспечение и лицензии

Все компоненты допускают развёртывание внутри контура без обращения к зарубежным сервисам. Ограничение соревнования на российское или локальное размещение языковой модели выполнено, модель по умолчанию выключена.

| Компонент | Роль | Лицензия | Условие для пилота |
| --- | --- | --- | --- |
| Python 3.11 и стандартная библиотека | среда исполнения API и конвейера | PSF License | свободное использование, зеркало пакетов внутри контура |
| FastAPI, pydantic, uvicorn | HTTP API и проверка схем | MIT и BSD | свободное использование |
| PostgreSQL с PostGIS | хранение агрегатов и витрин | PostgreSQL License, GPL 2.0 для расширения PostGIS | свободное использование, сведения о лицензии в паспорте поставки |
| Столбцовые файлы Parquet и pyarrow | обмен пакетами данных | Apache License 2.0 | свободное использование |
| React, Vite, TypeScript | интерфейс | MIT, Apache License 2.0 | свободное использование |
| MapLibre GL JS | отображение карты | BSD 3-Clause | свободное использование |
| PMTiles и Protomaps | свои тайлы карты | BSD 3-Clause для библиотеки, ODbL для данных OSM | атрибуция OpenStreetMap обязательна |
| Данные OpenStreetMap | геослои городов | ODbL 1.0 | атрибуция на карте и в отчёте |
| Данные ГИР БО | отчётность организаций | условия сервиса ФНС | только публичные сведения, персональные данные не переносятся |
| Локальная языковая модель | пояснения к отчёту | зависит от выбранной модели, план на модель с лицензией Apache 2.0 или MIT | запуск на своём оборудовании, без обращения к внешним API |

Отдельно проверяется лицензия PostGIS. Расширение распространяется по GPL 2.0, но используется как отдельный серверный процесс и на код сервиса не распространяется.

## Что нужно сделать к пилоту

Осталось согласовать с банком пять вопросов. Оператором персональных данных должен остаться банк, для этого нужен договор поручения на обработку и перечень данных, передаваемых в сервис. Порог агрегации 10 точек и 100 операций нужно подтвердить у службы безопасности. Хранение журнала обращений задаётся политикой банка, срок в сервисе не зашит. Языковую модель допускается включать только после проверки, что каждое число пояснения есть в отчёте. Сканирование зависимостей и контрольные суммы пакетов данных нужно включить в сборку до начала пилота.
