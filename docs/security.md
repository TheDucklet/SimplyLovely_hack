# Защита данных

Документ описывает, какие данные обрабатывает ГеоСтарт, как сервис разворачивается в контуре банка и что нужно сделать для соответствия 152-ФЗ и требованиям информационной безопасности при пилоте. Требования трека допускают неполное соответствие нормативам на этапе соревнования, но ждут понятного пути к нему, поэтому разделы ниже разделяют сделанное в MVP и план на второй спринт.

## Обрабатываемые данные

| Источник | Что используется | Персональные данные | Где хранится | Условия использования |
| --- | --- | --- | --- | --- |
| OpenStreetMap | здания, точки интереса, границы, адреса домов | нет | `data/raw/osm/`, `data/interim/osm/` | лицензия ODbL, на карте и в отчёте нужна атрибуция «© участники OpenStreetMap» |
| Росстат | численность населения субъектов | нет | `config/pipeline.yaml` | открытые данные |
| Портал открытых данных Москвы | название, сеть, вид, число мест и координаты заведений общепита | нет, телефоны заведений не сохраняются | `data/raw/mos_ru/` | открытые данные по постановлению Правительства РФ № 583, нужна ссылка на data.mos.ru |
| Работа России | название вакансии, вилка зарплаты, дата | нет после минимизации | `data/raw/trudvsem/` | открытое API |
| Исследование команды | параметры ниш, аренда, налоги | нет | `research/` | ссылки на источники в файлах |
| Запрос пользователя | город, ниша, координаты точки, площадь, ставка аренды | нет | не сохраняется | – |

Ответ API Работы России содержит имя контактного лица работодателя, телефон и электронную почту. Конвейер сохраняет в кэш только пять полей вакансии (`src/geostart/pipeline/trudvsem.py:minimize_vacancy`), а прежние кэши очищаются при первом чтении, что проверяет тест `test_vacancy_cache_keeps_no_contacts`. Записи проблемных интервью команды хранятся отдельно от репозитория в закрытой папке, в материалах проекта респонденты обозначены кодами.

## Персональные данные

В MVP сервис не обрабатывает персональные данные. Запрос к API содержит только параметры места и не связан с личностью пользователя, а отчёт рассчитывается заново и не сохраняется. При пилоте в ВТБ Бизнес личность клиента остаётся в системах банка. ГеоСтарт получает от банка параметры запроса и, при необходимости, псевдоним пользователя для журнала, а сохранять отчёт в карточке клиента будет банк своими средствами. Оператором персональных данных в такой схеме остаётся банк, и ГеоСтарт не расширяет состав обрабатываемых им сведений.

## Данные банка в пилоте

Точность модели выиграет от оборотов эквайринга по районам, но такие данные допускаются только как обезличенные агрегаты:

- агрегат строится по ячейке H3 разрешения 8 (около 0,7 км²), месяцу и группе ОКВЭД;
- агрегат публикуется, если в нём не меньше 10 торговых точек и 100 операций, иначе ячейка объединяется с соседними;
- выручка отдельной точки, реквизиты и идентификаторы клиентов в ГеоСтарт не передаются;
- расчёт агрегатов выполняет подразделение банка внутри своего контура, ГеоСтарт получает готовую таблицу.

Пороги 10 точек и 100 операций служат стартовыми значениями и согласуются со службой информационной безопасности банка.

## Развёртывание в контуре банка

Во время работы сервис не обращается к внешним сетям. В контур банка устанавливаются:

- API на FastAPI в контейнере;
- статическая сборка интерфейса за веб-сервером банка;
- данные в файлах Parquet, со второго спринта в PostgreSQL с PostGIS;
- собственный сервер тайлов карты, адрес задаётся переменной окружения интерфейса;
- локальная языковая модель для пояснений, если эта функция будет включена.

Обновление данных идёт пакетами. Конвейер запускается в отдельном сегменте с доступом к открытым источникам, собирает архив с версией данных и контрольными суммами, после проверки архив переносится в контур и подключается без перезапуска кода. Версия данных возвращается в каждом ответе API в поле `data_version`, благодаря чему любой отчёт можно воспроизвести.

## Роли и доступ

| Роль | Доступ |
| --- | --- |
| Предприниматель | отчёты по адресам через ВТБ Бизнес, вход через систему аутентификации банка |
| Сотрудник банка | отчёты и режим проверки бизнес-плана заёмщика |
| Инженер данных | загрузка и проверка пакетов данных, без доступа к журналам пользователей |
| Администратор | развёртывание, журналы, мониторинг |
| Разработчик команды | доступа к рабочему контуру нет, работает на синтетических и открытых данных |

## Журнал и мониторинг

Журнал API фиксирует время, путь, код ответа, длительность и псевдоним пользователя, если его передал банк. Координаты и параметры запроса в журнал не пишутся, так как вместе с псевдонимом они раскрывают планы конкретного предпринимателя. Срок хранения журнала задаёт политика банка.

## Угрозы и меры

| Угроза | Мера в MVP | Мера к пилоту |
| --- | --- | --- |
| Подмена или порча открытых данных | выгрузка OSM закреплена по дате, параметры с источниками | контрольные суммы пакетов, проверка распределений перед подключением |
| Некорректный ввод в API | проверка схем pydantic, ограничения на координаты и площадь | ограничение частоты запросов на шлюзе банка |
| Уязвимости зависимостей | версии закреплены в `uv.lock` | сканирование зависимостей в CI, зеркало пакетов внутри контура |
| Утечка ключей и паролей | ключи в `.env`, файл исключён из git | хранилище секретов банка |
| Вымышленные числа в пояснении языковой модели | функция не включена | проверка, что каждое число пояснения есть в отчёте, запуск модели on-prem |
| Раскрытие планов клиента | запросы не сохраняются | журнал без координат, доступ к журналу только у администратора |

## Соответствие требованиям

| Требование | Состояние |
| --- | --- |
| 152-ФЗ «О персональных данных» | MVP персональных данных не обрабатывает, при пилоте оператором остаётся банк |
| 115-ФЗ о противодействии легализации доходов | сервис не проводит и не анализирует операции клиентов, требования применяются к процессам банка |
| Требования ИБ банка (ГОСТ Р 57580.1-2017 как ориентир) | работа без внешних сетей, роли, журнал, обновление пакетами, детали согласуются при пилоте |
| Лицензия ODbL | атрибуция OpenStreetMap выводится на карте и в отчёте |
| Условия data.mos.ru | ссылка на портал выводится рядом с атрибуцией OpenStreetMap |

## План на второй спринт

1. Хранилище PostgreSQL с PostGIS и отдельными ролями для чтения API и загрузки данных сделано заранее (docs/storage.md), во втором спринте на базу переводится модель.
2. Аутентификация через заголовки шлюза банка и журнал API в описанном формате.
3. Контейнеры API и интерфейса, сборка без доступа в интернет из зеркала пакетов.
4. Сканирование зависимостей в CI.
5. Контрольные суммы и версия в пакете данных.
