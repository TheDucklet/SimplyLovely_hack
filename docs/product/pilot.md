# План внедрения и развития

## 1. Что уже готово к концу первого спринта

Работает сквозной сценарий на двух городах и двух нишах. Москва покрыта 8 717 ячейками, 9 381 конкурентом и 91 867 адресами, Тула покрыта 3 029 ячейками, 500 конкурентами и 26 204 адресами. API на FastAPI отвечает по реальным данным и расчётам модели, интерфейс собран на MapLibre и deck.gl, демо-стенд поднимается в Docker одной командой. Готовы комплект аналитики по проблеме, рынку и метрикам, сводка шести интервью и итоги опроса.

## 2. Доработки второго спринта, 16-29 ноября

| Направление | Работа | Результат к концу спринта |
| --- | --- | --- |
| Модель | Калибровка прогноза выручки по бухгалтерской отчётности ГИР БО, расчёт MAPE на отложенной выборке, покрытие коридора p10-p90 | Отчёт о качестве модели с MAPE не выше 25% и покрытием не ниже 80% |
| Данные | Дозагрузка 2-3 городов через конфигурацию, хранилище PostgreSQL с PostGIS вместо файлов | Подключение нового города без правки кода |
| Ниши | Параметры розницы у дома и бытовых услуг | Четыре ниши в карте и отчётах |
| Интерфейс | Экспорт отчёта в PDF как черновик бизнес-плана, сравнение двух адресов в одной таблице, юзабилити-тест с пятью пользователями | Готовый черновик бизнес-плана и список правок по итогам теста |
| Защита данных | Контур без доступа в интернет, роли и журнал доступа, документ по 152-ФЗ и требованиям ИБ | Развёртывание в контуре банка по инструкции |
| Пояснения | Локальная языковая модель для текстовых пояснений к отчёту, запуск on-prem | Русские пояснения без передачи данных наружу |

## 3. Доработки третьего спринта, 3-8 декабря

Третий спринт закрывает проверку эффекта и сценарий промышленного запуска. В него входят A/B-тест конверсии в заявку, сценарий пилота и масштабирования, отчёт о качестве модели для жюри, финальная полировка интерфейса и запись демонстрационного видео. Финал хакатона 11 декабря.

## 4. Сценарий пилота

| Параметр | Значение |
| --- | --- |
| Регионы | Москва в пределах МКАД и Тульская область |
| Сегмент | Начинающие предприниматели, открывающие кофейню или пункт выдачи заказов, и действующие клиенты микробизнеса, планирующие новую точку |
| Канал | Виджет на витрине регистрации бизнеса и в кабинете ВТБ Бизнес |
| Длительность | 8 недель, из них 6 недель на вход пользователей и 2 недели на дозревание договора аренды |
| Группы | Группа А видит базовый виджет, группа Б видит виджет с баннером, черновиком бизнес-плана и кнопками банковских продуктов |
| Объём | 303 участника на группу, набор покрывается трафиком четырёх ниш с запасом |
| Цель по заявкам | 118 заявок за пилот, 15% от показов и 33% от построивших отчёт |
| Метрики успеха | Доля построивших отчёт выросла с 45% до 53%, доля одобренных кредитных заявок в когорте, средний чек подключённых услуг, время загрузки кабинета не выросло |
| Условие остановки | Доля заявок от показов ниже 8% или рост времени загрузки кабинета выше 10% |

## 5. Масштабирование

Новый город подключается через конфигурацию, если для него доступны границы, сетка H3, жители и работающие, конкуренты из OpenStreetMap и ставки аренды по объявлениям. Каталог источников в репозитории описывает покрытие и лицензии. Следующая волна городов включает Московскую область, Екатеринбург, Казань и Нижний Новгород. Ниши расширяются от кофейни и пункта выдачи к рознице у дома и бытовым услугам, параметры для них готовятся во втором спринте. В промышленном контуре сервис переходит на хранилище PostgreSQL с PostGIS и развёртывание в Docker в закрытом контуре банка.

## 6. Требования банка к внедрению

| Требование | Как выполняем |
| --- | --- |
| Развёртывание on-prem без доступа в интернет | Docker compose с образами, загруженными в контур банка, автономный режим описан в документации |
| 152-ФЗ и требования ИБ | Сервис хранит обезличенные агрегаты по ячейкам, персональные данные не обрабатываются, тексты пояснений считаются локальной моделью |
| Журнал доступа и роли | Роли пользователя и аналитика, журнал доступа к отчётам и данным в хранилище |
| Интеграция с ВТБ Бизнес | Виджет в интерфейсе кабинета, единый вход, передача идентификатора отчёта в CRM, кнопки счёта, эквайринга и кредита |
| Нагрузка | Расчёт одного отчёта отвечает за секунды, карта города готовится заранее и кэшируется, стенд выдерживает пиковую нагрузку витрины |
| Прозрачность модели | Методика, источники и допущения описаны для кредитного специалиста, отчёт показывает факторы оценки и диапазон p10-p50-p90 |

## 7. Что нужно от банка для пилота

От банка нужны трафик витрины регистрации бизнеса и кабинета действующего клиента, доступ к продуктовой аналитике по конверсиям в счёт, эквайринг и кредит, менеджеры малого бизнеса для интервью и проверки сценария кредитного специалиста, тестовый контур для развёртывания и юридическая проверка текстов отчёта и заявки. Отдельно нужен доступ к историческим данным по одобренным заявкам на открытие точки для сверки прогноза с фактическим решением банка.

## 8. Риски и способы их снятия

| Риск | Снятие |
| --- | --- |
| Модель ошибается в рублях | Отчёт показывает диапазон и риск, калибровка по ГИР БО во втором спринте, MAPE контролируется на отложенной выборке |
| Конверсия в заявку ниже допущения | A/B-тест с промежуточным контролем доли после 303 участников на группу, окно набора продлевается |
| Данные по городу неполные | Каталог источников фиксирует покрытие и лицензии, Тула отмечена как город с неполным покрытием конкурентов |
| Банк не пропускает внешний сервис в контур | Развёртывание on-prem в Docker, локальная модель пояснений, работа без интернета |
| Выборка интервью и опроса не репрезентативна | Ограничения указаны в итогах, выводы переносятся в пилот с проверкой на реальном трафике |

## 9. Итоговый результат для банка

Пилот даёт проверяемую воронку от показа виджета до заявки на продукт, измеренный прирост конверсии в отчёт и заявку, оценку качества прогноза и готовый контур внедрения. При подтверждении гипотез сервис масштабируется на новые города и ниши и становится частью пути клиента при открытии точки, что снижает риск кредита и увеличивает число активных клиентов малого бизнеса.
