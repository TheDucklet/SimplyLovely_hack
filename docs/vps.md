# Развёртывание на VPS

Публичный стенд работает на сервере Никиты по адресу `http://fintech.shenti.space`. Внешний nginx сервера принимает запросы через Cloudflare и передаёт их на `127.0.0.1:8081`, где слушает контейнер `web` стенда. Конфигурация лежит в `compose.vps.yml` и `docker/web/nginx.vps.conf`, образы те же, что у [демо-стенда](demo.md).

## Ограничения сервера

На сервере 2 vCPU и 1,87 ГБ памяти без swap, параллельно работают VPN (3x-ui, около 130 МБ) и проект Альфа-хакатона на порту 8080 с лимитами 1,45 ГБ. На 2026-10-31 свободно около 990 МБ, стенду выделено не больше 690 МБ памяти и 1 vCPU суммарно.

| Контейнер | Лимит памяти | Лимит CPU | Замер 2026-10-31 |
| --- | --- | --- | --- |
| `api` | 640 МБ, своп запрещён | 0,8 | 320 МБ в покое, 386 МБ при пересчёте карты на старте, 506 МБ при 8 параллельных отчётах |
| `web` | 48 МБ, своп запрещён | 0,2 | 12-14 МБ |

Суммарно 688 МБ и 1,0 vCPU. Лимиты заданы через cgroups, поэтому при выходе за них ядро завершает процесс внутри контейнера, а не службы сервера. Контейнер перезапускается сам (`restart: unless-stopped`). Журналы контейнеров ограничены тремя файлами по 10 МБ.

Образы собираются не на сервере. Сборка интерфейса Vite в контейнере с лимитом 768 МБ упала с ошибкой `JavaScript heap out of memory`, на общем сервере она вытеснила бы VPN. Образы собирает Фёдор и передаёт архивом, `compose.vps.yml` использует их с `pull_policy: never`.

## Сеть и безопасность

| Что | Как устроено |
| --- | --- |
| порт | только `127.0.0.1:8081`, на `0.0.0.0` ничего не открыто, `network_mode: host` не используется, API наружу не публикуется |
| пользователь | `api` работает с uid и gid пользователя `fintechhack` из `.env`, файлы в `data/scores/` принадлежат ему, sudo не нужен |
| адрес клиента | nginx стенда берёт его из `CF-Connecting-IP`, при отсутствии заголовка из адреса соединения, и передаёт в `X-Forwarded-For` и `X-Real-IP`, uvicorn доверяет заголовкам через `FORWARDED_ALLOW_IPS` |
| частота запросов | с одного адреса не больше 2 отчётов в секунду с запасом 20 и 10 остальных запросов API в секунду с запасом 60, сверх нормы ответ 429 |
| CORS | интерфейс и API отдаются с одного адреса, настройка CORS не нужна |
| авторизация | нет, сервис не хранит данных пользователей и не ставит куки |

## Подготовка образов (Фёдор)

На итоговом `main` в корне клона:

```
docker compose -f compose.demo.yml build
docker save geostart-demo-api geostart-demo-web | gzip > geostart_images_<ГГГГ-ММ-ДД>.tar.gz
```

Архив весит около 420 МБ. Вместе с ним Никита получает архив данных `geostart_data_2026-10-16_v2.zip` (3,7 МБ).

## Первый запуск (Никита)

Перед запуском проверьте сервер. `uname -m` должен вывести `x86_64`, `docker ps` должен работать без sudo, свободного места на диске нужно не меньше 3 ГБ (`df -h ~`).

1. Скопируйте оба архива в домашний каталог `fintechhack`, например через `scp`.
2. Клонируйте репозиторий и распакуйте данные в его корень:

```
git clone https://github.com/TheDucklet/SimplyLovely_hack.git geostart
cd geostart
python3 -m zipfile -e ~/geostart_data_2026-10-16_v2.zip .
ls data/processed
```

Последняя команда выводит `moscow` и `tula`.

3. Загрузите образы и запишите uid пользователя:

```
gunzip -c ~/geostart_images_<ГГГГ-ММ-ДД>.tar.gz | docker load
echo "GEOSTART_UID=$(id -u)" > .env
echo "GEOSTART_GID=$(id -g)" >> .env
```

4. Запустите стенд:

```
docker compose -f compose.vps.yml pull
docker compose -f compose.vps.yml up -d --wait
```

`pull` пропускает оба образа, они уже загружены. Первый старт занимает около минуты, `api` пересчитывает карту.

## Проверка

| Команда | Ожидаемый результат |
| --- | --- |
| `curl -s http://127.0.0.1:8081/api/v1/health` | `{"status":"ok","mode":"data","data_version":"2026-10-16"}` |
| `docker compose -f compose.vps.yml ps` | оба контейнера в состоянии `healthy` |
| `docker stats --no-stream` | `api` до 640 МБ, `web` до 48 МБ |
| `ss -ltn \| grep 8081` | слушает только `127.0.0.1:8081` |
| открыть `http://fintech.shenti.space` | карта Москвы с ячейками, внизу версия данных 2026-10-16 |

Если `api` не стал `healthy`, причину покажет `docker compose -f compose.vps.yml logs api`.

## Обновление и остановка

Новую версию кода Фёдор присылает новым архивом образов. Никита выполняет `git pull`, загружает образы командой из шага 3 и повторяет `docker compose -f compose.vps.yml up -d --wait`. Новый архив данных распаковывается поверх `data/`, после чего достаточно `docker compose -f compose.vps.yml restart api`.

Остановка стенда:

```
docker compose -f compose.vps.yml down
```
