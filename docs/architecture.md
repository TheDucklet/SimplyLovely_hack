# Архитектура

ГеоСтарт состоит из четырёх частей, которые обмениваются данными через файлы Parquet и HTTP. Такое разделение позволяет каждому участнику разрабатывать свою часть на синтетических данных или заглушках, не дожидаясь остальных.

## Поток данных

```
открытые источники → pipeline → data/processed/<city> → model → data/scores → api → web
research/ (параметры ниш, аренда, налоги) → model
```

| Компонент | Каталог | Владелец | Вход | Выход |
| --- | --- | --- | --- | --- |
| Конвейер | `src/geostart/pipeline/` | Фёдор | OpenStreetMap, Реформа ЖКХ и ГИС ЖКХ, data.mos.ru, Работа России | `data/processed/<city>/*.parquet` |
| Модель | `src/geostart/model/` | Роман | `data/processed/`, `research/` | `data/scores/<city>_<niche>.parquet`, `LocationReport` |
| API | `src/geostart/api/` | Фёдор | `data/processed/`, `data/scores/`, функции модели | HTTP `/api/v1` |
| Интерфейс | `web/` | Алексей | HTTP `/api/v1` | карта и отчёт в браузере |
| Продукт | `docs/product/` | Никита, переносит Фёдор | интервью, опрос, открытые источники | проблема, рынок, метрики, опрос |

Общие модели ответов (`CityInfo`, `HexesResponse`, `LocationReport` и другие) лежат в `src/geostart/schemas.py:LocationReport` и используются моделью и API одновременно, поэтому формат ответа задаётся в одном месте. Чтение конфигурации городов и ниш выполняет `src/geostart/config.py:load_cities` и `load_niches`, пути к каталогам задаёт `src/geostart/settings.py`.

## Режимы API

Пока реальные расчёты не подключены, API работает в режиме заглушек (`GEOSTART_USE_MOCKS=true`). Заглушки строятся из тех же синтетических данных, что и файлы генератора `src/geostart/pipeline/fixtures.py:build_hex_features`, поэтому ячейки, конкуренты и адреса в ответах API совпадают с файлами в `data/processed/`. Формулы заглушек находятся в `src/geostart/api/mocks.py` и служат только для разработки интерфейса, расчётная модель Романа их заменит.

## Ограничения контура банка

Во время работы сервис не обращается к внешним API. Все данные загружает конвейер заранее, а API и интерфейс читают только локальные файлы. Единственное внешнее обращение интерфейса – подложка карты, её адрес задаётся переменной окружения, чтобы в контуре банка подставить собственный сервер тайлов.

## Работа с репозиторием

Для каждой задачи создаётся ветка `s1/<имя>/<id>-<кратко>`, изменения попадают в `main` только через pull request с прошедшим CI. Сообщения коммитов пишутся по-английски в повелительном наклонении, документация и тексты для пользователя по-русски. Участник меняет только каталоги, владельцем которых он указан в таблице выше. Данные, ключи и файл `.env` в репозиторий не попадают.
