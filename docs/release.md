# Обновление данных и выкладка

Новая версия проходит три шага. Сначала пересчитываются город и ниши со сравнением с прошлой версией по порогам, затем собирается архив данных с манифестом, и одна команда выкладывает его вместе с образами на стенд. Образы API и интерфейса собирает CI и публикует в реестр GitHub.

## Пересчёт города и ниши

```
uv run python -m geostart.release rebuild --city tula --niche all
```

Команда делает следующее:

1. Описывает текущие данные манифестом и копирует файлы выбранного города и ниш в `data/releases/previous/`.
2. Запускает конвейер `geostart.pipeline` по городу и расчёт модели по каждой нише.
3. Строит манифест новой версии и сравнивает его с прошлым по порогам из `config/release.yaml`.
4. Пишет отчёт `data/releases/<версия>/report.md`, проверки в `checks.json` и манифест версии.
5. Проверяет полноту и диапазоны данных города ([quality.md](quality.md)) и пишет отчёт `quality.md` рядом.
6. Если все проверки в пределах порогов и ошибок качества нет, записывает `data/manifest.json`. Иначе возвращает прежние файлы и завершается с кодом 2.

| Параметр | Назначение |
| --- | --- |
| `--city` | код города или `all` |
| `--niche` | код ниши или `all`, по умолчанию `all` |
| `--skip-pipeline` | только расчёт модели по готовым данным, например после правки параметров в `research/` |
| `--skip-wages` | оставить собранные ранее зарплаты, сбор вакансий Работы России занимает несколько минут |
| `--accept` | оставить новую версию, даже если расхождения выше порогов, после разбора отчёта |

При ошибке конвейера или модели прежние файлы тоже возвращаются. Полный пересчёт Тулы по семи нишам с готовыми слоями OSM занял 26 секунд, только модель по одной нише 8 секунд (замер 2026-11-20).

Версия данных имеет вид `ГГГГ-ММ-ДД.xxxxxxxx`, где после даты стоят первые 8 знаков SHA-256 от списка контрольных сумм файлов. Одинаковые файлы дают одинаковый хвост версии.

## Пороги расхождений

Манифест хранит по каждому городу число ячеек, жителей, работающих, адресов, конкурентов по нишам, строк зарплат и площадь границы. По каждому расчёту города и ниши он хранит число ячеек, медиану и 90-й процентиль выручки p50, медианы прибыли и окупаемости и доли уровней риска. Изменение считается как модуль разницы, делённый на прежнее значение, но не меньше нижней границы из раздела `floors`, чтобы малые числа вроде 12 конкурентов не давали ложных срабатываний.

| Показатель | Порог |
| --- | --- |
| ячеек города и расчёта | 5% |
| площадь границы | 3% |
| жителей | 10% |
| работающих, адресов | 15% |
| конкурентов ниши | 25%, нижняя граница 20 |
| строк зарплат | 50%, нижняя граница 4 |
| медиана выручки p50 | 20% |
| 90-й процентиль выручки p50 | 25% |
| медианы прибыли и окупаемости | 30%, нижние границы 50 000 ₽ и 6 месяцев |
| доля каждого уровня риска | 15 процентных пунктов |
| доля ячеек, где выручка p50 изменилась больше чем на 50% | 10% |

Последняя проверка сравнивает расчёты по каждой ячейке и выполняется, когда доступны файлы обеих версий. Новый город или расчёт проходит проверку с пометкой, а пропавший считается расхождением.

Две версии можно сравнить и без пересчёта, например перед заменой архива данных на стенде:

```
uv run python -m geostart.release compare путь/к/старому/data
uv run python -m geostart.release compare old_manifest.json new_manifest.json --json
```

## Архив данных

```
uv run python -m geostart.release package --output dist --with-basemap
```

Команда проверяет качество данных, при ошибках архив не собирается без флага `--force`. Затем она пишет `data/manifest.json` и собирает `dist/geostart_data_<версия>.zip` с файлами `data/processed/`, `data/scores/`, манифестом, отчётом о качестве `data/quality.md` и подложкой PMTiles, если указан `--with-basemap`. Рядом кладётся файл `.sha256`. Архив распаковывается в корень репозитория. Команда `uv run python -m geostart.release verify` сверяет файлы в `data/` с контрольными суммами манифеста.

## Образы в CI

Workflow `.github/workflows/images.yml` собирает образы `docker/api/Dockerfile` и `docker/web/Dockerfile` при каждом pull request с изменениями кода и при слиянии в `main`. После слияния и для тегов `v*` образы публикуются в реестр GitHub.

| Образ | Теги |
| --- | --- |
| `ghcr.io/theducklet/geostart-api` | `main`, `sha-<коммит>`, версия из тега `v1.2.3` |
| `ghcr.io/theducklet/geostart-web` | те же |

Слои кэшируются в GitHub Actions, поэтому при неизменных зависимостях повторно собираются только слои с кодом. После публикации задача `prune` оставляет две последних версии помимо тега `main` и версий релизов, так как бесплатное хранилище пакетов закрытого репозитория ограничено 500 МБ. Образ API без кэша uv (`UV_NO_CACHE=1`) уменьшился с 1,8 до 1,1 ГБ, в сжатом виде образ API весит 258 МБ, образ интерфейса 23 МБ (замер 2026-11-20).

## Выкладка на стенд

```
scripts/deploy_stand.sh --tag main --data ~/geostart_data_<версия>.zip
```

Скрипт выполняется на сервере в каталоге клона и делает следующее:

1. Загружает образы `geostart-api` и `geostart-web` с нужным тегом из реестра и запоминает образы работающей версии.
2. Если передан архив данных, сверяет его контрольную сумму, копирует текущие данные в `data/releases/stand-backup-<время>/`, распаковывает архив и сверяет файлы с манифестом.
3. Запускает `docker compose -f compose.vps.yml up -d --wait`.
4. Проверяет главную страницу, `/api/v1/health`, ответ API на данные (200 или 401 при включённом входе), тайл подложки и начало входа, каждую проверку повторяет до 30 секунд.
5. При любой ошибке возвращает прежние образы и данные и выводит последние строки журнала `api`.

| Параметр | Назначение |
| --- | --- |
| `--tag` | тег образов, по умолчанию `main` |
| `--data` | архив данных из `geostart.release package` |
| `--images` | архив образов из `docker save` вместо реестра, если сервер не видит ghcr.io |
| `--no-pull` | образы уже загружены на сервер |

Для загрузки из закрытого реестра на сервере один раз выполняется `docker login ghcr.io` с токеном GitHub с правом `read:packages`. Токен создаёт и вводит человек, в репозиторий и чат он не попадает. Без доступа к реестру остаётся прежний путь с архивом образов и параметром `--images`.

Скрипт проверен 2026-11-20 на Docker Desktop с `compose.vps.yml` и локальными образами. Выкладка с архивом данных проходит за 40 секунд. Если подставить вместо образа API образ без сервиса, проверка API не проходит, и скрипт возвращает прежние образы. Загрузка из реестра проверится на сервере после первой публикации образов.
