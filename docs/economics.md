# Финансовый движок

Пакет `src/geostart/economics/` считает помесячную финансовую модель новой точки малого бизнеса на горизонте 12-120 месяцев. Движок отвечает на вопросы банка и предпринимателя о сумме вложений, сроке окупаемости, точке безубыточности, нагрузке кредита и подходящем налоговом режиме. Расчёт выполняется по 200 сценариям, поэтому каждый показатель возвращается диапазоном p10-p50-p90.

Движок не зависит от геоданных. Выручку он получает из одного из трёх источников, и модель Хаффа ГеоСтарта служит только одним из них. Благодаря такому разделению банк может передать в движок оценку выручки своей геоплатформы и получить финансовый расчёт без карты ГеоСтарта.

## Модули

| Модуль | Назначение |
| --- | --- |
| `norms.py` | загрузка и проверка нормативов из `research/economics/norms.yaml` |
| `sampling.py` | сценарии по оценке p10-p50-p90 и сводка результатов |
| `taxes.py` | УСН «Доходы», УСН «Доходы минус расходы», патент, АУСН, взносы ИП за себя, НДС на УСН |
| `credit.py` | аннуитетный и дифференцированный график с льготным периодом, коэффициент покрытия долга, предельный кредит, кредитные продукты из `research/credit/products.yaml` |
| `engine.py` | помесячный расчёт и показатели, без чтения файлов |
| `service.py` | сборка входа из запроса API, выбор налогового режима, ответ API v2 |

Функции `engine.py` принимают массивы numpy и работают одинаково для любой ниши. Ниша влияет на расчёт только через параметры `research/niche_params/<niche>.yaml` и блок ниши в нормативах.

## Источники выручки

Выручка задаётся полем `demand` запроса:

- `geostart` – модель Хаффа по координатам точки, 200 сценариев параметров спроса из `research/niche_params`, ставка аренды берётся по району точки;
- `revenue` – внешняя оценка выручки в месяц p10-p50-p90, например от геоплатформы банка, поле `provider` попадает в ответ;
- `traffic` – трафик в день, конверсия и средний чек, выручка равна их произведению, умноженному на 30,4 дня;
- `geoplatform` – траты категории по квадратам 500×500 м из геоплатформы банка, разделённые с конкурентами по модели Хаффа, описание в разделе «Источник геоплатформы».

Для источников `revenue` и `traffic` ставка аренды берётся медианой ставок города, если пользователь не задал свою. Плановая выручка понимается как средний месяц после выхода на план в ценах первого года.

## Источник геоплатформы

Геоплатформа банка, например GEO.Platforma, отдаёт данные по квадратам 500×500 м. Модуль `src/geostart/economics/geoplatform.py` принимает по каждому квадрату границы, траты категории в месяц p10-p50-p90 и необязательный поток людей в день и переводит их в выручку новой точки:

1. Траты квадрата делятся поровну между ячейками H3 города, центры которых лежат в квадрате.
2. Берутся ячейки в радиусе пешей доступности точки, радиус и параметры притяжения берутся из 200 сценариев модели спроса ниши.
3. Доля новой точки в тратах ячейки считается по формуле Хаффа с конкурентами ниши из OpenStreetMap и data.mos.ru и весом внешней альтернативы, как в модели спроса.
4. Выручка равна сумме долей по ячейкам и ограничивается пределом покупок в день, если он задан у ниши.

Уровень квантиля трат один для всех квадратов в сценарии, поэтому хорошие и плохие сценарии не усредняются между соседними квадратами. Спрос пункта выдачи описывается заказами маркетплейсов, траты покупателей к нему не применимы, поэтому для него источник `geoplatform` возвращает ошибку 422.

Квадраты передаются в запросе полем `demand.squares`. Если поле пустое, берутся синтетические слои заглушки из `data/geoplatform/<город>.parquet`, которые собирает команда

```
uv run python -m geostart.economics.geoplatform_stub --city all
```

Заглушка складывает по квадратам спрос модели ГеоСтарт при медианных параметрах ниши и умножает его на логнормальный шум с σ = 0,2, диапазон p10-p90 равен 0,75-1,3 от медианы. Поток людей заглушки равен 0,5 человека на жителя, 1 на работающего, 250 на остановку и 3000 у выхода метро в день. Заглушка повторяет формат данных геоплатформы и не описывает реальные траты.

Скрипт `scripts/geoplatform_demo.py` считает один и тот же адрес по модели ГеоСтарт и по заглушке геоплатформы при неизменном движке, открытие в январе 2027 года, без кредита.

## Сценарии

Оценка p10-p50-p90 превращается в 200 значений по кусочно-линейной функции квантилей. Значения на уровнях 0,1, 0,5 и 0,9 совпадают с оценкой, за пределами p10 и p90 функция продолжается с тем же наклоном и обрезается снизу нулём. Уровни берутся равномерной сеткой и перемешиваются генератором с зерном 2026, поэтому одинаковый запрос всегда даёт одинаковый ответ. Параметры затрат перемешиваются независимо друг от друга.

Площадь, штат, доля себестоимости, прочие расходы и вложения берутся из параметров ниши города. Значение, заданное в запросе, заменяет диапазон во всех сценариях.

## Помесячный расчёт

Месяц 1 соответствует первому месяцу работы точки, вложения делаются в месяц 0. Месяц и год открытия задаются полями `start_month` и `start_year`. Без них расчёт начинается со следующего календарного месяца. Для каждого сценария и месяца движок считает:

- выручку как плановую выручку, умноженную на долю выхода на план, сезонный множитель календарного месяца и индекс цен;
- себестоимость как долю выручки;
- аренду как площадь, умноженную на ставку, с ежегодной индексацией;
- зарплату по медиане вакансий профессии в городе и взносы работодателя с учётом пониженного тарифа для кофеен, на АУСН вместо взносов начисляется фиксированный взнос на травматизм;
- прочие расходы с ежегодной индексацией;
- EBITDA как выручку за вычетом перечисленных расходов;
- проценты и погашение кредита по графику;
- налоги по выбранному режиму.

Индексы растут ступенькой раз в 12 месяцев от открытия. Сезонность нормируется к среднему 1, поэтому годовая выручка после выхода на план не зависит от сезонности.

Вложения состоят из капитальных затрат, паушального взноса франшизы, обеспечительного платежа по аренде и оборотного запаса. Обеспечительный платёж равен числу месяцев аренды из нормативов, оборотный запас равен числу месяцев себестоимости при плановой выручке. Оба возвращаются в последнем месяце горизонта. Стоимость бизнеса в конце горизонта не учитывается, и NPV получается консервативным.

## Структура вложений и амортизация

Капитальные затраты делятся на статьи по долям из блока `capex_structure` нормативов ниши. Для кофейни ремонт занимает 35%, оборудование 45%, мебель и вывеска 10%, прочие расходы 10%. Для пункта выдачи ремонт занимает 45%, стеллажи и мебель 25%, оргтехника и видеонаблюдение 20%, прочие расходы 10%. Доли и сроки пока остаются допущениями команды и уточняются в задаче S2-Ц8.

Каждая статья амортизируется линейно в течение своего срока использования, паушальный взнос амортизируется за 60 месяцев. Амортизация выводится в строках месяцев и лет вместе с EBIT, на денежный поток она не влияет. На УСН «Доходы минус расходы» вложения и паушальный взнос уменьшают базу первого налогового года целиком, как расходы на основные средства в год ввода.

## Налоги

Налоги считаются по календарным годам. Первый и последний год могут быть неполными, тогда фиксированные взносы ИП берутся пропорционально числу месяцев. Годовая сумма распределяется по месяцам пропорционально выручке.

| Режим | Расчёт |
| --- | --- |
| УСН «Доходы» 6% | 6% выручки уменьшаются на взносы работодателя и взносы ИП за себя, но не больше чем на 50% при наличии сотрудников |
| УСН «Доходы минус расходы» 15% | 15% от выручки за вычетом расходов, процентов, взносов ИП и вложений первого года, не меньше 1% выручки, убыток переносится на следующие годы |
| Патент | годовая стоимость патента города уменьшается на взносы так же, как УСН «Доходы» |
| АУСН «Доходы» 8% | 8% выручки без уменьшения на взносы |
| АУСН «Доходы минус расходы» 20% | 20% от выручки за вычетом расходов, не меньше 3% выручки, перенос убытка не применяется |

Взносы ИП за себя равны фиксированной сумме 57 390 ₽ в год и 1% дохода свыше 300 000 ₽, дополнительная часть ограничена 321 818 ₽. Для патента доходом считается потенциальный доход, равный стоимости патента, делённой на 6%. Для ООО взносы за себя не начисляются, налог на прибыль и дивиденды не моделируются.

Патент доступен только ИП в нише кофейни. В Москве стоимость берётся по ставке ЦАО, если точка в ЦАО или округ неизвестен, и по минимальной ставке для остальных округов. В Туле стоимость считается по площади зала, доля зала задаётся нормативом. Сценарий, в котором годовая выручка больше 20 млн ₽ или штат больше 15 человек, теряет право на патент и считается по УСН «Доходы», доля таких сценариев выводится в предупреждениях.

На АУСН работодатель не платит взносы на пенсионное, медицинское и социальное страхование, а ИП не платит фиксированные взносы за себя. Вместо них начисляется фиксированный взнос на травматизм 2 959 ₽ в год по постановлению Правительства РФ от 01.11.2025 № 1729, в модели он начисляется один раз на работодателя. АУСН доступна ИП и ООО при годовой выручке до 60 млн ₽ и штате до 5 человек в регионах, где режим введён. Даты начала по городам сервиса лежат в разделе `ausn.regions` файла `research/taxes/2026.yaml`. Эксперимент действует до 31.12.2027, поэтому годы после 2027 считаются по УСН «Доходы» или УСН «Доходы минус расходы» с обычными взносами, о чём ответ сообщает в предупреждениях. Сценарий с выручкой или штатом выше лимита тоже считается по УСН. Плательщики АУСН не платят НДС, кроме НДС при ввозе товаров.

НДС на УСН определяется по годовой выручке календарного года. До 20 млн ₽ НДС не начисляется, до 272,5 млн ₽ применяется 5%, до 490,5 млн ₽ 7%, выше 22%. Переход на ставку внутри года не моделируется.

При `tax.regime = "auto"` движок рассчитывает все доступные режимы и выбирает режим с наименьшей медианой суммы налогов и взносов работодателя за весь горизонт. Взносы входят в сравнение, так как на АУСН они почти исчезают, а на патенте и УСН «Доходы» уменьшают налог. Сравнение режимов с причиной недоступности возвращается в `tax.options`, а поле `tax.explanation` объясняет выбор и называет разницу с ближайшим режимом в рублях.

## Кредит

Сумма кредита задаётся абсолютной величиной или долей вложений и не может превышать вложения. Ставка и срок по умолчанию берутся из нормативов. Поле `financing.product` подставляет ставку, срок, график и льготный период кредитного продукта из `research/credit/products.yaml`, явные поля запроса имеют приоритет. Продукт `vtb_express` описывает экспресс-кредит ВТБ для малого бизнеса со ставкой от 26%, сроком до 36 месяцев и лимитом 10 млн ₽. Банк выдаёт его бизнесу не младше 12 месяцев, поэтому для нового бизнеса ответ предупреждает о несоответствии. Возраст бизнеса передаётся полем `financing.business_age_months`, список продуктов с источниками отдаёт `GET /api/v2/credit-products`.

В льготный период из поля `grace_months` платятся только проценты, основной долг гасится за оставшийся срок. Аннуитетный платёж считается по месячной ставке, равной годовой ставке, делённой на 12. Дифференцированный график гасит основной долг равными частями.

Коэффициент покрытия долга (далее – DSCR) считается как отношение операционного денежного потока к платежам по кредиту по годам и по месяцам. В ответе есть DSCR первого года, минимальный DSCR по годам и по месяцам и медиана числа месяцев с DSCR ниже порога. Строки месяцев содержат DSCR выбранного сценария. Предельный кредит равен годовому денежному потоку после выхода на план, делённому на порог DSCR и на наибольший годовой платёж по кредиту в 1 ₽.

## Показатели

| Показатель | Определение |
| --- | --- |
| NPV | сумма дисконтированных операционных потоков и возврата залога и запаса за вычетом вложений, ставка по умолчанию равна ключевой ставке и премии за риск |
| IRR | годовая ставка, при которой NPV равен нулю, пусто, если поток не меняет знак |
| Окупаемость | первый месяц, в котором накопленный операционный поток покрывает вложения, с дробной частью, пусто, если вложения не окупаются за горизонт |
| Дисконтированная окупаемость | то же по дисконтированному потоку |
| Месяц выхода в плюс | первый месяц, в котором прибыль после процентов и налогов положительна |
| Точка безубыточности | выручка в месяц, при которой прибыль после налогов в ценах первого года равна нулю, ищется делением отрезка с налогами выбранного режима |
| Единиц в день | точка безубыточности, делённая на средний чек или выплату за заказ и на 30,4 дня |
| Запас прочности | доля, на которую плановая выручка превышает точку безубыточности |
| Вероятность убытка | доля сценариев, где прибыль месяца после выхода на план отрицательна |

Пустые значения окупаемости при расчёте квантилей считаются бесконечно большими, пустые значения IRR и запаса прочности считаются бесконечно малыми. Если больше половины сценариев не окупаются, медиана окупаемости приходит пустой. Уровень риска определяется по вероятности убытка с порогами 20% и 50%, как в отчёте API v1.

Таблицы `monthly`, `years` и `steady_month` показывают один сценарий с медианным NPV, чтобы строки сходились по сумме. Полоса `cash_band` показывает p10-p50-p90 накопленного потока по всем сценариям.

## Нормативы

Файл `research/economics/norms.yaml` хранит общие нормативы и нормативы ниш. У каждого значения есть единица, источник и пояснение. Значение без подтверждённого источника отмечено `source: null` и выводится в допущениях ответа с пометкой «допущение без источника». Источники для таких значений собираются в задаче S2-Ц8.

| Норматив | Значение | Источник |
| --- | --- | --- |
| Ключевая ставка | 14% | решение Банка России от 23.10.2026 |
| Премия за риск | 6 п. п. | допущение |
| Инфляция и индексация цен | 6,5% в год | середина прогноза Банка России 6-7% |
| Индексация аренды и рост зарплат | 6,5% в год | допущение |
| Ставка кредита по умолчанию | 19% | ключевая ставка и 5 п. п., допущение до задачи S2-Ц3 |
| Срок кредита по умолчанию | 36 месяцев | допущение |
| Ставка экспресс-кредита ВТБ | 26% | карточка продукта, проверено 18.11.2026 |
| Порог DSCR | 1,25 | допущение |

Нормативы заданы для всех семи ниш, у пяти ниш второго спринта все значения пока помечены как допущения. Для новой ниши в нормативы добавляется блок с выходом на план, сезонностью, оборотным запасом, обеспечительным платежом, долей зала и названием единицы продаж. Без такого блока API v2 возвращает ошибку 422 с текстом «Для ниши … нет нормативов финансового движка».
