# Инструкции для ИИ-агентов

Файл читают все агенты, которые работают в репозитории ГеоСтарта (Codex, Claude Code и другие). Требования ниже обязательны для любой задачи, даже если в промте о них не сказано.

## Правила текста и кода

Полный текст правил команды лежит в [docs/rules.md](docs/rules.md), агент читает его перед началом работы и соблюдает целиком. Часть 1 действует для README, `docs/`, описаний pull request, отчётов и текстов интерфейса, часть 2 – для кода. Основные требования:

- в коде нет комментариев и docstring, разрешены только машинные директивы вида `# noqa: E501`;
- имена переменных, функций, классов и файлов на английском, тексты для пользователя, ошибки и документация на русском;
- аннотации типов у публичных функций, константы вместо магических чисел, перечисления вместо строковых литералов состояний;
- в тексте среднее тире «–», длинное «—» только в подписях рисунков и таблиц, диапазоны через дефис, без неразрывных пробелов и дефисов;
- без двоеточий посреди предложения, без предложений, начинающихся с «Это», без слов из запретного списка правил;
- изменение поведения и обновление документации идут в одном коммите.

Источник правил – файл «Правила текста и кода.md» капитана, `docs/rules.md` обновляется вместе с ним.

## Контракт и границы

Структура репозитория, схемы данных, интерфейс модели и HTTP API описаны в [docs/contracts.md](docs/contracts.md). Агент меняет только каталоги своего владельца из таблицы в [docs/architecture.md](docs/architecture.md). Изменение контракта согласует Фёдор, агент вместо самовольной правки описывает нужное изменение в отчёте.

## Порядок работы

- перед задачей выполняется `git pull` на `main`, работа идёт в ветке `s1/<имя>/<id>-<кратко>`;
- коммиты по-английски в повелительном наклонении, заголовок до 72 символов;
- перед коммитом проходят `uv run ruff format --check`, `uv run ruff check`, `uv run pytest`, для `web/` – `npm run lint` и `npm run build`;
- в `main` напрямую не пишет никто, изменения идут через pull request, push выполняется только после подтверждения человека;
- коммиты и pull request создаются от имени человека, без строк `Co-Authored-By`, подписей вида «Generated with …» и других пометок нейросети, облачные боты для pull request не используются;
- данные, ключи, пароли и `.env` в репозиторий не попадают, регистрацию и получение ключей выполняет человек;
- если задача неясна или противоречит контракту, агент останавливается и задаёт вопрос человеку.

## Отчёт

После задачи агент пишет отчёт по шаблону `.team/Шаблон отчёта.md` (комплект спринта у человека) в `.team/out/report_<ID>.md` и собирает архив `S1_<Имя>_<ID>_<ГГГГ-ММ-ДД>.zip` с отчётом и `changes.patch` (`git diff main...HEAD > changes.patch`) в `.team/out/`. Отчёт пишется по правилам части 1, в нём честно указывается, что не сделано и почему.
